# OKX 策略逆向系统独立评审报告 / OKX-REV-20261017-001

## 0. 结论与边界

**结论：CHANGES_REQUIRED。** 当前仓库是可进一步迭代的离线研究原型，不可将其输出当作已验证的真实 OKX 机器人策略，也不允许将其用于自动实盘交易。**P0 表示“真实策略结论发布门禁”，不表示项目不能启动或 demo 全部失效。**

本次审阅基于 GitHub 仓库 **main@f90916496bb75571e781000a7e71ed3dcdc5e29d** 的源文件：ingest.py、cli.py、detectors.py、features.py、episodes.py、backtest.py、models.py、security.py、synth.py、tests 和仓库内示例报告。**静态审查：未在本会话的 Python 环境运行仓库 pytest、demo，也没有读取用户的真实账户数据。** 开发报告中的 18 passed 和 SYNTHETIC_DEMO/GRID/MEDIUM 属于开发侧自述及已提交制品，不等于独立复测通过。

已具备：离线 CLI、示例数据生成、CSV/XLSX 基础解析、简单结构检测、RSI/EMA/布林/突破特征、样本报告与现货单入单出回测。缺失或未经验证：可靠机器人订单归属、真实数据摄取、信号因果归因、候选策略选择隔离、真实网格/多层 DCA 状态机、正确持仓对账和合约 PnL。

## 1. P0：会污染策略判断或真实数据账本（逐项验收门禁）

### OKX-P0-01 [INFERENCE] 未来信号可匹配过去的成交

- 证据：src/okx_reverse/detectors.py 的 _match() 使用 abs(fill_ts - s) <= tol_ms；match_signals_to_fills()/evaluate_rule_oos() 调用它。
- 原因：成交之前尚未产生的 RSI/EMA/突破信号也可能算作命中；默认允许 ±2 小时，测试用例未防止反向匹配。
- 处理：区分 signal_available_at、order_created_at、fill_at。最少要求 signal_available_at <= fill_at，优先匹配委托发出时间；仅允许可解释的因果延迟区间，并记录未匹配、冲突和多个信号竞争。
- 验收 A01：信号时间=13:00、成交=12:00 必须拒绝；信号=11:00、成交=12:00 可在显式一小时容差内匹配；同一成交不可重复匹配。

### OKX-P0-02 [VALIDATION] 用最终测试集选最佳指标，样本外测试失效

- 证据：src/okx_reverse/cli.py cmd_infer 的 best_buy / best_sell 从 v["test"]["precision"] 取最大值；然后写入 reconstructed_strategy.json。
- 原因：虽然有 60/20/20 切分，但测试集参与选择；并不存在真正的冻结参数后一次性独立评估。
- 处理：训练集拟合阈值/参数，验证集选候选及阈值，冻结模型后一次评估测试集。若参数是预先规定的，则须记录规则来源与冻结时点；严禁依赖测试集的排名选规则。
- 验收 A02：变更测试集信号和成交，不得改变已冻结的 rule_id、参数、阈值或模型版本；测试结果可以变化。

### OKX-P0-03 [CLASSIFICATION] 网格强度分级仅依赖交易数量，误报风险高

- 证据：detectors.py detect_grid() 先对全部买/卖成交价排序后相邻做差，双方 kind 一致且 support>=8 即给 MEDIUM；实际示例买/卖 arith_cv≈1.18/1.26，拟合十分松散。
- 原因：sorted-fill spacing != 挂单阶梯；动态网格、同价多次成交、滑点、部分成交、价格路径都被忽略；大样本随机成交仍可能被误认网格。
- 处理：建立时间有序的价格层簇、订单/成交去重、容差和有效网格覆盖率，计算间距残差、层位复现率及交易路径一致性；需与随机/趋势/DCA 负样本比较并保留反证。证据差时输出 LOW/UNDETERMINED。
- 验收 A03：独立生成的固定算术网格、几何网格与随机成交，分别得出可解释的区分结果；原示例高 CV 数据不得仅因笔数多而升级为 MEDIUM。

### OKX-P0-04 [INGEST] 最小真实导出可能导入报错，数据集被“最新文件”覆盖

- 证据：ingest.py 使用 df.get("pos_side","").astype(...), df.get("reduce_only","").astype(...), df.get("bot_id","").fillna(...)；缺列时 fallback 为 str，不支持 .astype/.fillna。cli.py 的 _save_state() 只更新 data/normalized/latest.json，_load_latest() 仅读最新单个 source_id。
- 原因：普遍缺少可选列的导出文件不能被安全解析；分月导出相互覆盖，机器人历史分析不完整。
- 处理：建立显式 schema/默认 Series，必填列 fail-fast；所有导入追加到不可变来源清单，跨文件按交易所唯一成交标识幂等合并，保持 source lineage；按 bot_id、instrument、product、时间范围隔离分析，UNKNOWN 不得默认为该机器人。处理订单与成交两种文件的独立 schema。
- 验收 A04-A06：仅含 time/side/price/qty 的最小 CSV 导入不因可选列缺失崩溃；两个月份文件合并后记录均保留；同毫秒不同 trade_id 保留，相同 trade_id 跨导出不重复；混合机器人不得合并推断。

### OKX-P0-05 [LEDGER] Episode 与费用账本可能失真

- 证据：episodes.py 中 ep_id 在 pos==0 开仓时+1，close_row() 再+1；fees 在每个 episode 结束后未清零；盈亏函数只用均价、min(entry_qty,exit_qty)，没有按 fee_ccy 换算。cli.py cmd_backtest 直接 float(fills["fee"].sum())，不同币种混加。先卖后买、反向跨零仓、pos_side 亦未被正确建模。
- 原因：Episode ID 跳号、跨回合手续费污染和币种混加可导致净盈亏错误；初始仓位未知时无法可靠构建已实现盈亏。
- 处理：以逐笔持仓/现金流账本实现开仓、部分减仓、平仓、跨零反转；净值和已实现盈亏使用统一计价币种+兑换率来源，无法折算则禁止输出精确净收益；单次 Episode ID 单调+1，费用在每回合重置。现货与合约长/短分别建模。
- 验收 A07-A09：两个独立往返 Episode ID 仅 1、2，手续费各自隔离；以 BTC+USDT 手续费混合输入时没有兑换率则 PnL 状态 UNVERIFIABLE；初始仓未知和合约反转必须告警且无伪精确值。

### OKX-P0-06 [REPLAY] GRID 的分类结果与执行回测模型不一致

- 证据：artifacts/strategies/reconstructed_strategy.json 写 GRID，但 entry_rule=rsi_below_30、exit_rule=rsi_above_70；cli.py cmd_infer 将最优 RSI 名直接写到 recon，cmd_backtest 调用 run_strategy()；backtest.py 仅支持单次入场/离场，没有网格阶梯和 DCA 加仓状态机。
- 原因：RSI 现货回测不能验证“重建 GRID”是否复现原机器人；即便回测结果好，也不是该机器人的复现能力。
- 处理：reconstructed_strategy.json 强制区分 observed_structure、signal_hypothesis、executable_model、validated_on_holdout；如果 GRID/DCA 不支持执行则返回 NOT_IMPLEMENTED/UNVERIFIABLE，不得拿 RSI 结果冒充网格回测。实现可审计的网格/DCA 状态机后再启用复现比较。
- 验收 A10：GRID 无状态机时禁止生成“GRID 回测通过”；实现后需比对逐笔成交方向、触发价、成交时间、数量、持仓路径，附假阳性/假阴性指标及差异清单。

### OKX-P0-07 [QUALITY] 多个测试只检查表面形式，存在恒真断言

- 证据：tests/test_g08_g18.py: test_g17 的 assert cli.main(["demo"]) == 0 or True，以及文件存在判断的 or True；test_g08 仅核对 detect_grid 返回固定 family 字符串；test_g10 仅核对 precision 字段存在；test_g16 仅检查 train/validation/test 键；tests/test_g01_g07.py 的 G06 只检查输入 DataFrame 本就包含 fee_ccy。
- 原因：18 passed 不等于交易结果、无未来信息、正确费用或样本外识别通过。
- 处理：替换恒真断言；增加真实输出数值 oracle、负样本、突变测试、边界和反例，保护程序退出码。
- 验收 A11：故意使 demo 返回非零、故意混合币种求和、故意让未来信号匹配过去成交时，对应测试必须失败；每个 G01–G18 的测试须指向实质行为。

## 2. P1：真实数据推进所需的工程加固

- OKX-P1-01：行情归属。cli.py _find_market() 即使没有匹配 inst_id 也返回其他交易对 K 线；必须 fail closed，验证 inst_id、市场种类、时间戳、区间、一致性。
- OKX-P1-02：行情确认。ingest.py import_market_bars() 将 confirmed 一律设为 True，bar_end_ms 可由不足样本推断出 0；应按源数据确认只用完整已收盘 K 线、拒绝缺少时间边界的记录。
- OKX-P1-03：汇总状态伪通过。cli.py 无实际动态验证直接写 lookahead_check="PASS"；改为具版本号的验收证据或 NOT_CHECKED。
- OKX-P1-04：回测现金/基准一致性。backtest.py 入场 spend 可达 cash*0.95 且另扣手续费（极端 fee 下可透支），买入持有使用 99.9% 与策略 95% 不同资本配置、且费用处理不一致；需统一资产/手续费/滑点/资金约束。
- OKX-P1-05：DCA 的 max_consecutive_buys 来自仅保留 buy 的 g，因此永远≈n_buys；按原始事件流和 episode 重做，分别计算连续买入和层级倍率。
- OKX-P1-06：净持仓/双向持仓/资金费率/合约面值、保证金、强平业务未完整建模；若真实样本是 SWAP/FUTURES，必须降级并阻止不受支持的 PnL 结论。
- OKX-P1-07：数据安全。security.py 的正则静态扫描只检查若干字符串，不足以证明不可达网络写调用。当前已查源码未发现实盘 HTTP 集成，但未来接 API 应采用默认离线、明确定义只读 allowlist、权限验收、密钥脱敏及网络模拟拦截测试。
- OKX-P1-08：回溯来源和结果对应。demo 与真实数据的 report/backtest 使用固定文件名，报告可能混入上一次运行的旧制品；每次输出必须绑定 run_id、dataset fingerprint、code SHA，报告检查同一 run_id。
- OKX-P1-09：时区参数在导入解析时未生效，缺失时区的日期按 UTC 解释；真实中国本地时间会错位，应指定来源时区并输出标准 UTC 毫秒。
- OKX-P1-10：添加针对多笔部分成交、同价重复、跨日、连续多个机器人、不同交易对及混合人工订单的独立压力用例。
